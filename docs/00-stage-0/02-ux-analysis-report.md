## 1. Целевая аудитория

### Primary
Возраст 22–40, Краснодар+, техника = рабочий инструмент.  
Профили: разработчики, дизайнеры, маркетологи, IT, стримеры, киберспорт, SMB, самозанятые.

Устройства (приоритет): смартфоны, ноутбуки, игровые ноутбуки, ПК → планшеты, приставки, мониторы.

### Secondary
- Родители (доверие > цена)
- Студенты (цена + прозрачность)
- Владельцы малого бизнеса (минимальный простой)

### Anti-persona
Выбор только по минимальной цене, игнор качества/гарантий — **не целевая**.

## 3. Боли, страхи, причины отказа

### Страхи (влияние)
1. Подмена комплектующих — очень высокий  
2. Рост стоимости после диагностики — очень высокий  
3. Некачественный ремонт — очень высокий  
4. Потеря данных — высокий  
5. Долгий ремонт — высокий  
6. Формальная гарантия — средний  

### Причины отказа от сайта
- Устаревший / шаблонный дизайн  
- Перегруз информацией  
- Нет ответов на главные вопросы  
- Нет фото мастерской / людей  
- Нереалистичные обещания («за 15 минут»)  
- Сложные формы / попапы

## 5. Product Psychology

### Эмоциональный путь
`Тревога → Интерес → Доверие → Уверенность → Действие`

### Когнитивные триггеры (этично)
- Social Proof — отзывы, 600+ ремонтов  
- Authority — мастера, оборудование, процесс  
- Cognitive Fluency — короткие блоки, иерархия  
- Loss Aversion — сохранность данных/деталей/времени  
- Peak-End — сильный Hero + сильный финальный CTA  
- Choice Architecture — 1 primary + 1–2 alt CTA  

### Trust Framework (6 уровней)
1. Визуальное  
2. Информационное  
3. Репутационное  
4. Процессное  
5. Эмоциональное  
6. Техническое (скорость, формы, стабильность)

### Правило контента
Текст без ответа на один из вопросов пользователя — удалить:
- Почему доверять?
- Почему лучше?
- Как проходит ремонт?
- Что с устройством?
- Сколько времени?
- Почему цена не «уплывёт»?
- Что после ремонта?

## 6. Customer Journey → UX-требования

| Этап | Состояние | Что должен дать сайт |
|------|-----------|----------------------|
| Первое впечатление | Любопытство / скепсис | Премиальный Hero, скорость, бренд |
| Формирование доверия | Осторожность | Услуги + доказательства |
| Процесс / гарантии | Снижение тревоги | Прозрачные этапы, фиксация цены |
| Решение | Уверенность | Отзывы, мастера, цифры |
| Действие | Готовность | Простая форма + каналы связи |

---

## 7. UX Principles для реализации

1. Один экран — одна задача  
2. Не продавать слишком рано  
3. Обещание + доказательство рядом  
4. Следующий шаг всегда очевиден  
5. CTA доступны с ключевых экранов, но не давят в Hero  
6. Mobile First (PRD) + паритет качества Desktop  
7. Touch targets ≥ 44×44  
8. После отправки формы — ясный сценарий («перезвоним за N минут»)

## 8. Точки входа и CTA-модель

### Точки входа
- Органический поиск / карты  
- Реклама / соцсети  
- Рекомендация  
- Прямой заход  

### Primary CTA
Оставить заявку на ремонт / диагностику

### Secondary CTA
Заказать звонок · Позвонить · VK · MAX · Маршрут

### CTA placement (UX)
- Header (desktop): компактный secondary или primary  
- После About / trust: primary  
- Contacts: полный набор  
- Sticky mobile bar (опционально, после fold) — без перекрытия контента  

**Запрет:** агрессивные popup на входе; несколько равнозначных CTA в Hero.
